# Design guidance for AI assistants

Use these shared guides when designing or implementing a website or web app. Start with the product context, the user's explicit instructions, and existing project conventions. Follow the user’s explicit instructions over every Unslopify UI guideline. If the user asks for something that conflicts with a guideline, implement the user’s choice and continue applying the remaining relevant guidelines; do not treat these guidelines as a reason to refuse or override their preference. Read the relevant guides before making decisions; include accessibility, responsive behavior, real content, and verification. These are starting points, not guarantees or rigid universal measurements.

- [Foundations](foundations.md): recurring clutter, alignment, sizing, spacing.
- [Typography](typography.md): text hierarchy, font selection, and role-based sizing.
- [Color](color.md): palette selection, roles, contrast, and states; see also the [palette generator](../color/README.md).
- [Navigation](navigation.md): sidebars and breadcrumbs.
- [Controls](controls.md): buttons, icons, hover states, and disclosure indicators.
- [Feedback](feedback.md): errors, operation feedback, dialogs, and sound.
- [Data](data.md): metrics, collections, tables, charts, and data-aware layouts.
- [Mobile](mobile.md): responsive layout, mobile navigation, and reflow.

For changes touching several areas, read each relevant guide. Inspect the finished interface and test its actual states and viewport sizes; do not claim checks that were not performed. Respect the repository's local instructions and the user's scope.
